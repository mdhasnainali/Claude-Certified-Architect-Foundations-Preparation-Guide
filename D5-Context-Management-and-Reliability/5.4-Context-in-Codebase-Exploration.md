# 5.4 Context in Codebase Exploration

## Goal
After this you can keep a long codebase investigation sharp: subagents for the noisy digging, scratchpad files for findings, summaries between phases, a manifest for crash recovery, and `/compact`. *(Task statement 5.4)*

## Guess first
1. Two hours into exploring a repo, Claude starts saying "services typically use a repository pattern" instead of naming the classes it found earlier. What is happening?
2. You run `/compact`. Where should your key findings be so nothing important is lost?

## Idea
**Context degradation.** In long sessions the window fills with file reads and command output. Answers become inconsistent, and Claude falls back to "typical patterns" instead of the specific classes it discovered. Every token spends some of the model's attention budget.

Five counter-moves:

1. **Delegate verbose work to subagents.** Give each a focused question — "find all test files", "trace the refund flow dependencies". The digging happens in *their* context; the main agent gets a short summary (often 1–2k tokens) and keeps the big picture. In Claude Code the built-in **Explore** subagent does read-only searches (quick / medium / very thorough).
2. **Scratchpad files.** The agent writes key findings to a file (`notes/findings.md`) and reads it for later questions. Files survive compaction and restarts; chat history doesn't survive intact.
3. **Summarise between phases.** Before the next phase, condense what you learned and **inject that summary** into the next subagents' prompts, instead of letting them start blind or inherit noise.
4. **Crash recovery with a manifest.** Each agent exports its state (done, findings, next step) to a known location; a manifest lists them. After a crash, the coordinator loads the manifest and injects the state into the new agents' prompts.
5. **`/compact`** when verbose discovery output fills the context. It replaces the conversation with a structured summary.

**What survives `/compact` in Claude Code:** the root CLAUDE.md and unscoped rules are re-injected from disk; the plan from plan mode is re-injected; up to five recently read/edited files are re-read; path-scoped rules reload when matching files are touched. The **conversation itself is summarised** — so anything important must be in a file, not only in chat.

*In Python/ML terms:* like checkpointing training. You save `state_dict` every epoch so a crash resumes from the checkpoint, not from scratch.

## Code

**File:** [`codes/5_4_manifest.py`](codes/5_4_manifest.py) · run `make run 5_4_manifest`

Python 3.13+, offline, no API key. Save as `5_4_manifest.py`, run `python3 5_4_manifest.py`.

```python
# 5_4_manifest.py — Python 3.13+, offline. Crash recovery: agents save state; a new coordinator resumes from a manifest.
import json, pathlib, tempfile

STATE = pathlib.Path(tempfile.mkdtemp())

def save(agent: str, done: list[str], findings: list[str], next_step: str) -> None:
    (STATE / f"{agent}.json").write_text(
        json.dumps({"done": done, "findings": findings, "next": next_step})
    )
    manifest = {p.stem: p.name for p in STATE.glob("*.json") if p.stem != "manifest"}
    (STATE / "manifest.json").write_text(
        json.dumps(manifest)
    )  # one known place to look

save(
    "test-mapper",
    ["listed 212 test files"],
    ["pytest; shared fixtures in tests/conftest.py"],
    "find the 10 slowest tests",
)
save(
    "refund-tracer",
    ["traced refund_order → issue_refund → gateway.pay"],
    ["no retry on gateway timeout"],
    "check jobs/nightly.py",
)

# ---- the process crashes here; a fresh coordinator starts with an empty context ----
manifest = json.loads((STATE / "manifest.json").read_text())
lines = []
for agent, file in sorted(manifest.items()):
    s = json.loads((STATE / file).read_text())
    lines.append(
        f"- {agent}: done {s['done']}; found {s['findings']}; next: {s['next']}"
    )
print(
    "Resume the investigation. Saved state from before the restart:\n"
    + "\n".join(lines)
)
```

Expected output:
```
Resume the investigation. Saved state from before the restart:
- refund-tracer: done ['traced refund_order → issue_refund → gateway.pay']; found ['no retry on gateway timeout']; next: check jobs/nightly.py
- test-mapper: done ['listed 212 test files']; found ['pytest; shared fixtures in tests/conftest.py']; next: find the 10 slowest tests
```
That printed text is what the new coordinator puts into the subagents' prompts.

The same ideas inside Claude Code, as a prompt you can paste in any repo:
```text
Use the Explore agent to find all test files and their fixtures. Write a 10-line summary to notes/findings.md.
Then use a subagent to trace the refund flow's dependencies; append its summary to notes/findings.md.
For every later question in this session, read notes/findings.md first and cite file paths from it.
```

**Predict first, then check:** after the two phases above you run `/compact`. Which survives better — a detail that is only in the chat, or the same detail in `notes/findings.md`?

<details><summary>Answer</summary>

The file. Compaction summarises the chat and may drop details; the file is on disk, and Claude Code even re-reads recently edited files after compacting.

</details>

## When to use · gotchas
- Spot degradation early: vague "typical" answers, contradictions with earlier findings → act (delegate, write notes, compact or start fresh with a summary).
- Subagents need the question **and** the needed context in their prompt (they don't inherit yours — [1.3 Spawning Subagents and Passing Context](../D1-Agentic-Architecture-and-Orchestration/1.3-Spawning-Subagents-and-Passing-Context.md)).
- A scratchpad only helps if the agent is told to **read it** before answering.
- Save state at a **known location** with a manifest; ad-hoc files scattered in the repo are hard to resume from.
- Rules that must survive compaction belong in the root CLAUDE.md (path-scoped rules are summarised away until reloaded).

## Try it
*≤ 10 min.* Extend `save()` to also store `files_changed` (list of paths) and make the resume text say "Re-read these files before trusting old findings: …". Why does this matter? (Think [1.7 Sessions Resume and Fork](../D1-Agentic-Architecture-and-Orchestration/1.7-Sessions-Resume-and-Fork.md).)

<details><summary>Solution</summary>

```python
def save(agent, done, findings, next_step, files_changed=()):
    (STATE / f"{agent}.json").write_text(json.dumps(
        {"done": done, "findings": findings, "next": next_step, "files_changed": list(files_changed)}))
    (STATE / "manifest.json").write_text(json.dumps(
        {p.stem: p.name for p in STATE.glob("*.json") if p.stem != "manifest"}))

# in the resume loop:
#   if s["files_changed"]: lines.append(f"  Re-read before trusting old findings: {s['files_changed']}")
```
Saved findings can go stale when files change after they were recorded. Naming the changed files lets the new agent re-check only those — targeted re-analysis instead of full re-exploration.

</details>

## Quiz
**1.** Late in a long exploration, Claude's answers turn generic and contradict earlier findings. Best combination? A) Switch to a larger model · B) Keep key findings in a scratchpad file, delegate further digging to subagents, and compact · C) Ask Claude to try harder · D) Restart without notes

<details><summary>Answer</summary>

**B.** It removes the noise from the main context and keeps facts in a durable place. D throws away the work.

</details>

**2.** Why delegate "find all test files" to a subagent instead of doing it in the main conversation?

<details><summary>Answer</summary>

The verbose search output stays in the subagent's context; the main agent receives only a summary and keeps its context for coordination.

</details>

**3.** Phase 1 mapped the modules. You now spawn subagents for phase 2. What should their prompts contain?

<details><summary>Answer</summary>

A summary of phase 1's key findings, injected into their initial context — not the raw phase 1 output.

</details>

**4.** A multi-agent investigation crashes after an hour. How do you resume without redoing everything?

<details><summary>Answer</summary>

Each agent exported its state to a known location with a manifest; the coordinator loads the manifest on resume and injects that state into the agents' prompts.

</details>

**5.** What happens to the chat history on `/compact` in Claude Code, and what is re-injected?

<details><summary>Answer</summary>

The conversation is replaced by a structured summary. Root CLAUDE.md, unscoped rules and the plan are re-injected from disk, and up to five recently used files are re-read.

</details>
