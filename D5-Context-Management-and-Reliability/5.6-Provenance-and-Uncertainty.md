# 5.6 Provenance and Uncertainty

## Goal
After this you can keep every claim tied to its source through a multi-agent synthesis, and show conflicts and dates honestly instead of silently picking one value. *(Task statement 5.6)*

## Guess first
1. Two credible sources say 62% and 41%. Pick the newer one? Average them? Something else?
2. 30 findings are summarised into 5 bullets. What usually disappears first?

## Idea
**Summaries lose attribution.** When findings are compressed into prose, the link "this claim ← that source" breaks. The final report then has claims nobody can check.

**Claim–source mappings all the way through.** Require subagents to return structured items: claim, source (URL or document name), relevant excerpt, page, date. The synthesis agent must **keep and merge** these mappings, not rewrite them away (see [1.3 Spawning Subagents and Passing Context](../D1-Agentic-Architecture-and-Orchestration/1.3-Spawning-Subagents-and-Passing-Context.md)).

**Conflicts: annotate, don't pick.** Two credible sources disagree → show **both values with their sources**. The analysis step completes *with* the conflict marked, and the coordinator decides how to reconcile before synthesis. Choosing one at random hides real uncertainty.

**Dates prevent false contradictions.** 41% (2024) and 62% (2026) are not a conflict — they are a trend. Require publication or collection dates in every structured output.

**Report structure:**
- separate **well-established** findings (several sources agree) from **contested** ones and **single-source** ones;
- keep each source's original framing and method notes ("survey of 1,200 members", "company filing");
- render by content type: **financial data as tables, news as prose, technical findings as lists** — don't force one format on everything.

**Tools that help on the API:** Claude's **citations** feature (`"citations": {"enabled": true}` on document blocks) returns the exact cited text and its location with each claim. Anthropic's anti-hallucination advice: ground answers in quotes, and **retract any claim that has no supporting quote**.

*In Python terms:* keep the `source` and `date` columns through every `groupby` in pandas — don't aggregate them away.

```python
# 5_6_provenance.py — Python 3.13+, offline. Merge findings without losing sources; label agreement and conflict.
from collections import defaultdict

findings = [  # claim-source mappings returned by two subagents
    {
        "metric": "illustrators using AI weekly",
        "value": "62%",
        "source": "Survey A (example.org)",
        "date": "2026-03",
    },
    {
        "metric": "illustrators using AI weekly",
        "value": "41%",
        "source": "Poll B (example.net)",
        "date": "2024-05",
    },
    {
        "metric": "stock-music royalty change",
        "value": "-9%",
        "source": "Music report p.14",
        "date": "2025-11",
    },
    {
        "metric": "stock-music royalty change",
        "value": "-4%",
        "source": "Label filing",
        "date": "2025-11",
    },
    {
        "metric": "VFX artists using AI",
        "value": "1 in 3",
        "source": "Guild study",
        "date": "2026-01",
    },
    {
        "metric": "VFX artists using AI",
        "value": "1 in 3",
        "source": "Studio survey",
        "date": "2026-02",
    },
    {
        "metric": "novelists drafting with AI",
        "value": "18%",
        "source": "Author blog",
        "date": "2026-05",
    },
]
findings_by_metric = defaultdict(list)
for finding in findings:
    findings_by_metric[finding["metric"]].append(finding)

sections = {
    "Well-established": [],
    "Single source": [],
    "Changed over time": [],
    "Contested": [],
}
for metric, metric_findings in findings_by_metric.items():
    citations = "; ".join(
        f"{finding['value']} ({finding['source']}, {finding['date']})"
        for finding in metric_findings
    )
    values = {finding["value"] for finding in metric_findings}
    dates = {finding["date"] for finding in metric_findings}
    if len(metric_findings) == 1:
        sections["Single source"].append(f"{metric}: {citations}")
    elif len(values) == 1:  # 2+ sources agree
        sections["Well-established"].append(f"{metric}: {citations}")
    elif len(dates) > 1:  # different dates → a trend, not a contradiction
        sections["Changed over time"].append(f"{metric}: {citations}")
    else:  # same period, different values → keep both
        sections["Contested"].append(f"{metric}: sources disagree: {citations}")

for section, entries in sections.items():
    print(f"## {section}\n" + "\n".join(f"- {entry}" for entry in entries))
```

Expected output:
```
## Well-established
- VFX artists using AI: 1 in 3 (Guild study, 2026-01); 1 in 3 (Studio survey, 2026-02)
## Single source
- novelists drafting with AI: 18% (Author blog, 2026-05)
## Changed over time
- illustrators using AI weekly: 62% (Survey A (example.org), 2026-03); 41% (Poll B (example.net), 2024-05)
## Contested
- stock-music royalty change: sources disagree: -9% (Music report p.14, 2025-11); -4% (Label filing, 2025-11)
```

**Predict first, then change and run:** change Poll B's date from `2024-05` to `2026-03`. Where does the illustrators metric move?

<details><summary>Answer</summary>

To **Contested** — same period, different values. Without dates you can't tell a trend from a conflict, which is why dates must be in every structured output.

</details>

## When to use · gotchas
- No source → no claim in the final report (or mark it clearly as unsupported).
- Never average or "pick the most recent" silently between credible conflicting sources. Show both; let the coordinator or a human decide.
- Keep method context: a 50-person poll and a 10,000-person census are not equal evidence.
- A single source is not "well-established", however confident it sounds.
- Exam distractor: "the synthesis agent should choose the most reliable value" — the guide wants conflicts annotated with attribution.

```python
print("| metric | value | source | date |\n|---|---|---|---|")
for metric, metric_findings in findings_by_metric.items():
    if len({finding["value"] for finding in metric_findings}) > 1:  # trends and conflicts
        for finding in sorted(metric_findings, key=lambda finding: finding["date"]):
```

## Quiz
**1.** Two credible reports give different market-size figures for the same year. What should the synthesis do? A) Use the larger report's number · B) Average them · C) Include both with source attribution and mark the conflict · D) Drop the metric

<details><summary>Answer</summary>

**C.** Annotate conflicts with attribution; don't select arbitrarily.

</details>

**2.** The final report's claims have no sources, although subagents had them. Where did attribution break, and how do you prevent it?

<details><summary>Answer</summary>

During summarisation, claims were compressed without their sources. Require structured claim–source mappings from subagents and make synthesis preserve and merge them.

</details>

**3.** "Usage rose from 41% to 62%" was reported as a contradiction between sources. What was missing?

<details><summary>Answer</summary>

Publication/collection dates in the structured outputs — different years make it a trend, not a conflict.

</details>

**4.** How should a report present findings with different levels of support?

<details><summary>Answer</summary>

In explicit sections: well-established (multiple agreeing sources), contested (conflicting sources), single-source — with each source's original framing and method.

</details>

**5.** A research report mixes revenue numbers, news events and API changes, all as bullet lists. Better?

<details><summary>Answer</summary>

Render by type: financial data as tables, news as prose, technical findings as structured lists.

</details>
