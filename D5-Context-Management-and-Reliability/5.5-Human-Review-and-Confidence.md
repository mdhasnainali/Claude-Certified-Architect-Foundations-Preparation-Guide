# 5.5 Human Review and Confidence

## Goal
After this you can decide which extractions a human must check — using accuracy per segment and calibrated confidence, not one big average. *(Task statement 5.5)*

## Guess first
1. Your extraction pipeline is 97% accurate overall. Is it safe to stop human review?
2. The model reports confidence 0.9 on a field. Is that field right 90% of the time?

## Idea
You know this from ML work — it is classifier evaluation applied to an LLM pipeline.

**Averages hide weak segments.** 97% overall can mean 99% on typed invoices and 72% on handwritten ones — or 60% on one field such as dates. Before you reduce human review, **check accuracy by document type and by field**.

**Field-level confidence, calibrated.** Have the model output a confidence per field. Raw scores are not probabilities. **Calibrate** them against a **labeled validation set**: for each segment, find the threshold above which auto-accepted fields really meet your target (say 98% correct). Below it → human review.

**Route review by risk.** Send these to people first:
- low-confidence fields,
- documents that are ambiguous or contradict themselves (two different totals, unreadable dates).
Reviewer time is limited; spend it where errors are likely.

**Keep measuring after go-live.** Take a **stratified random sample** of *high-confidence* auto-accepted extractions (e.g. 5 per document type per week) and check them by hand. This measures the real error rate and catches **new** error patterns (a new invoice layout, a new vendor) that the old validation set never saw.

**Not the same as 5.2.** Self-reported confidence is a bad *escalation trigger* in a conversation. Here, confidence becomes useful only **after** it is calibrated on labeled data, per segment.

*In ML terms:* per-class precision/recall instead of overall accuracy, a reliability (calibration) curve, and stratified sampling for monitoring drift.

## Code

**File:** [`codes/5_5_calibrate.py`](codes/5_5_calibrate.py) · run `make run 5_5_calibrate`

Python 3.13+, offline, no API key. Synthetic but realistic numbers (fixed random seed). Save as `5_5_calibrate.py`, run `python3 5_5_calibrate.py`.

```python
# 5_5_calibrate.py — Python 3.13+, offline. Accuracy by segment, threshold calibration, stratified audit sample.
import random
from collections import defaultdict

random.seed(7)
rows = []  # labeled validation set: model confidence vs. the human-checked truth
for doc_type, n, p_ok in (("typed", 900, 0.99), ("handwritten", 100, 0.75)):
    for _ in range(n):
        ok = random.random() < p_ok
        conf = min(1.0, max(0.0, random.gauss(0.93 if ok else 0.72, 0.07)))
        rows.append({"doc_type": doc_type, "conf": conf, "ok": ok})

acc = lambda rs: sum(r["ok"] for r in rs) / len(rs)
by_type = defaultdict(list)
for r in rows:
    by_type[r["doc_type"]].append(r)
print(
    f"overall: {acc(rows):.1%}  |  "
    + "  ".join(f"{t}: {acc(rs):.1%} (n={len(rs)})" for t, rs in by_type.items())
)

for (
    t,
    rs,
) in (
    by_type.items()
):  # per segment: lowest threshold whose auto-accepted rows are >= 98% right
    best = next(
        (
            th / 100
            for th in range(50, 100)
            if (a := [r for r in rs if r["conf"] >= th / 100]) and acc(a) >= 0.98
        ),
        None,
    )
    auto = [r for r in rs if best is not None and r["conf"] >= best]
    print(
        f"{t:12} threshold={best}  auto-accept {len(auto)}/{len(rs)}  → {len(rs) - len(auto)} to human review"
    )

audit = {
    t: random.sample([r for r in rs if r["conf"] >= 0.9], 5)
    for t, rs in by_type.items()
}
print(
    "weekly audit sample (stratified, 5 per type):",
    {t: len(s) for t, s in audit.items()},
)
```

Expected output:
```
overall: 96.6%  |  typed: 99.3% (n=900)  handwritten: 72.0% (n=100)
typed        threshold=0.5  auto-accept 900/900  → 0 to human review
handwritten  threshold=0.83  auto-accept 68/100  → 32 to human review
weekly audit sample (stratified, 5 per type): {'typed': 5, 'handwritten': 5}
```
The overall 96.6% looks fine. The split shows the truth: handwritten documents need their own, much stricter threshold — about a third still go to people.

**Predict first, then change and run:** change the audit line to a plain `random.sample` of 10 rows from **all** high-confidence rows (not per type). How many handwritten rows will the audit usually contain?

<details><summary>Answer</summary>

Very few — 0 or 1 in about 8 of 10 weeks, because only ~8% of high-confidence rows are handwritten. A non-stratified sample hardly ever checks the risky segment. That's why the sample is stratified.

</details>

## When to use · gotchas
- Never automate on an aggregate number. Segment by document type **and** field first.
- Calibrate on **labeled** data you trust; re-calibrate when inputs change.
- Ambiguous or contradictory source documents go to humans even with high confidence.
- Keep sampling high-confidence output forever (lightly). Errors you don't sample, you don't see.
- Exam distractor: "97% overall → remove human review". Or "trust the model's raw confidence".

## Try it
*≤ 10 min.* Add a `field` dimension (`total`, `date`, `vendor`), make `date` fields on handwritten docs less accurate, and print accuracy per (doc_type, field).

<details><summary>Solution</summary>

```python
rows = []
for doc_type, n, p_ok in (("typed", 900, 0.99), ("handwritten", 100, 0.75)):
    for _ in range(n):
        field = random.choice(["total", "date", "vendor"])
        p = p_ok - (0.15 if doc_type == "handwritten" and field == "date" else 0)
        ok = random.random() < p
        rows.append({"doc_type": doc_type, "field": field, "ok": ok,
                     "conf": min(1.0, max(0.0, random.gauss(0.93 if ok else 0.72, 0.07)))})

seg = defaultdict(list)
for r in rows:
    seg[(r["doc_type"], r["field"])].append(r)
for key, rs in sorted(seg.items()):
    print(key, f"{acc(rs):.1%}", f"n={len(rs)}")
```
Handwritten `date` shows up as the weakest cell — invisible in the overall number.

</details>

## Quiz
**1.** Extraction accuracy is 97% overall. The team wants to stop human review for "high-confidence" outputs. What must happen first? A) Nothing, 97% is enough · B) Check accuracy by document type and field, and calibrate thresholds on a labeled set · C) Ask the model to be more careful · D) Use a bigger model

<details><summary>Answer</summary>

**B.** Aggregates can hide weak segments; thresholds need calibration before automation.

</details>

**2.** How do you keep measuring the error rate after high-confidence outputs are auto-accepted?

<details><summary>Answer</summary>

Stratified random sampling of high-confidence extractions (per document type), checked by humans — also catches new error patterns.

</details>

**3.** Reviewers can check 200 documents a day; 2,000 arrive. Which go to them?

<details><summary>Answer</summary>

Low-confidence fields and ambiguous or contradictory documents first — risk-based routing.

</details>

**4.** Why calibrate confidence on a labeled validation set?

<details><summary>Answer</summary>

The model's raw scores aren't true probabilities. Calibration shows which threshold actually gives the target accuracy for each segment.

</details>

**5.** Your audit samples 20 random high-confidence rows a week and never finds handwritten errors. Is handwritten safe?

<details><summary>Answer</summary>

Not proven — a non-stratified sample rarely includes the small segment. Stratify the sample by document type.

</details>
