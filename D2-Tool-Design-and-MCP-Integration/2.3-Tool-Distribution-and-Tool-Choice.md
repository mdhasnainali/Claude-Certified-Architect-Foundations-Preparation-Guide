# 2.3 Tool Distribution and Tool Choice

## Goal
After this you can give each agent a small, role-fitted tool set, and use `tool_choice` to control whether and which tool Claude calls. *(Task statement 2.3)*

## Guess first
1. Agent A has 18 tools, agent B has the 4–5 it needs. Which picks tools more reliably?
2. You need a tool call on **every** request, so the output is always structured. `auto`, `any`, or a forced tool?

## Idea
**Fewer tools, better choices.** Giving one agent 18 tools instead of 4–5 makes every decision harder and selection less reliable. Each tool definition also costs context.

**Out-of-role tools get misused.** A synthesis agent that also has web search starts searching instead of synthesising.

**Scoped access:**
- Each agent gets only the tools for its role (least privilege).
- Add a **narrow cross-role tool** for a frequent need. Example (official sample question 9): the synthesis agent gets `verify_fact` for simple checks (85% of cases); deep research still goes through the coordinator.
- **Constrain generic tools.** Replace `fetch_url` (any URL) with `load_document`, which accepts only valid document URLs from allowed sources.

**`tool_choice` options:**

| Value | Meaning | Use when |
|---|---|---|
| `{"type": "auto"}` | Claude decides; it may answer with plain text | Default, normal chat and agents |
| `{"type": "any"}` | Must call **some** tool; Claude picks which | Guarantee structured output when several extraction schemas exist and the document type is unknown |
| `{"type": "tool", "name": "X"}` | Must call **X** | Force a first step, e.g. `extract_metadata` before enrichment; later turns go back to `auto` |
| `{"type": "none"}` | No tools | Pure text turn |

With `any` or a forced tool, the response **starts** with the tool call: no text before it, and no thinking. `disable_parallel_tool_use: true` limits Claude to at most one call per response.

> [!WARNING]
> **Exam vs today's API**
> The exam treats `any` and forced tools as normal. On the newest models (Claude Opus 5.5, Sonnet 5.5, Fable 5.1/5.2) they return **400**. There you use `auto` + `strict: true` + a prompt that names the tool, and check that a call happened. Older models (e.g. Claude Opus 5) and Claude Haiku 5.5 still accept them. **On the exam, answer as the guide says.**

*In Python terms:* scoped tools are like dependency injection — pass a component only the services it needs, not the whole container. `tool_choice: tool` is calling a function directly instead of letting a dispatcher choose.

## Code

**File:** [`codes/2_3_force_tool.py`](codes/2_3_force_tool.py) · run `make run 2_3_force_tool`

Python 3.13+, `anthropic` 2.13. Needs `ANTHROPIC_API_KEY`; 3 small calls. Uses **Claude Haiku 5.5**: cheap, and it still accepts forced tool choice.
Save as `2_3_force_tool.py`, run `uv run --with anthropic python 2_3_force_tool.py`.

```python
# 2_3_force_tool.py — anthropic 2.13. Run: uv run --with anthropic python 2_3_force_tool.py
import anthropic

client = anthropic.Anthropic()

def obj(*names: str) -> dict:
    return {
        "type": "object",
        "properties": {n: {"type": "string"} for n in names},
        "required": list(names),
    }

TOOLS = [
    {
        "name": "extract_metadata",
        "input_schema": obj("title", "author", "date", "doc_type"),
        "description": "Extract title, author, date (YYYY-MM-DD) and document type from a document. Run first.",
    },
    {
        "name": "enrich_company",
        "input_schema": obj("company"),
        "description": "Look up industry and size for ONE company named in a document.",
    },
]
DOC = "Q3 Report — Acme Robotics. Author: Dana Lee. 2 Oct 2026. Revenue grew 12% on warehouse robots."
MODEL = "claude-haiku-5-5"  # accepts forced tool_choice; Opus 5.5 / Sonnet 5.5 return 400 for any/tool

for choice in (
    {"type": "auto"},
    {"type": "any"},
    {"type": "tool", "name": "extract_metadata"},
):
    r = client.messages.create(
        model=MODEL,
        max_tokens=1000,
        tools=TOOLS,
        tool_choice=choice,
        messages=[{"role": "user", "content": f"Here is a document:\n{DOC}"}],
    )
    calls = [(b.name, b.input) for b in r.content if b.type == "tool_use"]
    print(f"{choice['type']:5} stop={r.stop_reason:9} calls={calls}")
```

Possible output (the `auto` and `any` lines vary):
```
auto  stop=end_turn  calls=[]
any   stop=tool_use  calls=[('extract_metadata', {'title': 'Q3 Report', 'author': 'Dana Lee', 'date': '2026-10-02', 'doc_type': 'quarterly report'})]
tool  stop=tool_use  calls=[('extract_metadata', {'title': 'Q3 Report', 'author': 'Dana Lee', 'date': '2026-10-02', 'doc_type': 'quarterly report'})]
```
`auto` may just describe the document in text. `any` guarantees *a* tool call (could be `enrich_company`). `tool` guarantees *that* tool.

**Predict first, then change and run:** set `MODEL = "claude-opus-5-5"`. What happens on each of the three lines?

<details><summary>Answer</summary>

`auto` works. `any` raises `anthropic.BadRequestError` (400: `tool_choice: type "tool" and "any" are not supported for this model.`), so the loop stops there. On these models: `auto` + `strict: true` + "Use the extract_metadata tool", then check for a `tool_use` block.

</details>

## When to use · gotchas
- Start every agent with the **smallest** tool set; add tools only when a real task needs them.
- A cross-role tool should be **narrow** (simple fact check), not a copy of another agent's full toolbox.
- `any` guarantees a call, **not** which one. Need a specific first step → force that tool.
- Forcing a tool every turn traps the loop — Claude can never finish with text. Force the first step, then switch back to `auto`.
- Restricting tools is also safety: a read-only reviewer can't break files.

## Try it
*≤ 10 min.* Configure the synthesis subagent from sample question 9 in the Agent SDK: it may read files and call a `verify_fact` tool, but has no web search.

<details><summary>Solution</summary>

```python
from claude_agent_sdk import AgentDefinition, ClaudeAgentOptions, create_sdk_mcp_server, tool

@tool("verify_fact", "Check ONE short fact (date, name, number) against a trusted source. "
      "Returns {verified, source}. For anything needing research, report it to the coordinator.",
      {"claim": str})
async def verify_fact(args):
    return {"content": [{"type": "text", "text": '{"verified": true, "source": "..."}'}]}

synthesizer = AgentDefinition(
    description="Writes the cited report from findings given in its prompt.",
    prompt="Use only the findings given. Use verify_fact for simple checks; list bigger "
           "questions under 'Needs research' for the coordinator.",
    tools=["Read", "mcp__facts__verify_fact"])          # no WebSearch, no WebFetch
options = ClaudeAgentOptions(mcp_servers={"facts": create_sdk_mcp_server("facts", tools=[verify_fact])},
                             agents={"synthesizer": synthesizer},
                             allowed_tools=["Agent", "Read", "mcp__facts__verify_fact"])
```

</details>

## Quiz
**1.** One agent has 18 tools across search, billing, CRM and reporting. Tool picks are often wrong. Best direction? A) Longer system prompt · B) Split into role-scoped agents with 4–5 tools each · C) A bigger model · D) `tool_choice: any`

<details><summary>Answer</summary>

**B.** Too many tools raise decision complexity. Scoped toolsets per role fix the cause.

</details>

**2.** Documents arrive as invoices, contracts or receipts; each has its own extraction tool. Sometimes Claude answers in prose instead of calling one. Which `tool_choice`?

<details><summary>Answer</summary>

`{"type": "any"}` — a tool call is guaranteed, and Claude picks the right extraction schema for the unknown document type.

</details>

**3.** Enrichment tools must never run before `extract_metadata`. How do you use `tool_choice`?

<details><summary>Answer</summary>

Force `{"type": "tool", "name": "extract_metadata"}` on the first request; handle enrichment in follow-up turns with `auto`.

</details>

**4.** Why replace a generic `fetch_url` tool with `load_document`?

<details><summary>Answer</summary>

It constrains the tool to its real purpose — validated document URLs from allowed sources — so the agent can't fetch arbitrary pages.

</details>

**5.** Your synthesis agent keeps doing web searches instead of combining findings. Why, and fix?

<details><summary>Answer</summary>

It has tools outside its specialisation, so it misuses them. Remove the search tools from its toolset; give it at most a narrow `verify_fact` tool.

</details>
