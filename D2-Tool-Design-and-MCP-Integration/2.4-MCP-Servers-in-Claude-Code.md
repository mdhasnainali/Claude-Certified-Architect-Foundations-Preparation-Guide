# 2.4 MCP Servers in Claude Code

## Goal
After this you can put an MCP server at the right scope, keep secrets out of git, and expose a content catalog as a resource. *(Task statement 2.4)*

## Guess first
1. A new teammate clones the repo, but the team's Jira MCP server doesn't show up for them. Where was it probably configured?
2. Your agent makes 6 search calls just to learn which docs exist. What MCP feature could show it the list up front?

## Idea
**Where a server lives decides who gets it:**

| Scope | File | Loads in | Shared? | Use for |
|---|---|---|---|---|
| **Project** | `.mcp.json` in the repo root | this project | **Yes**, via git | Team tools (Jira, GitHub, internal KB) |
| **User** | `~/.claude.json` | all your projects | No | Personal / experimental servers |
| Local (default of `claude mcp add`) | `~/.claude.json`, under this project's path | this project | No | Private servers for one project |

Same server name in two scopes → local wins over project, project over user (the whole entry, no merging). Claude Code asks for approval before it uses project servers from a cloned `.mcp.json`.

**Secrets: environment variable expansion.** `.mcp.json` may use `${GITHUB_TOKEN}` or `${VAR:-default}` in `command`, `args`, `env`, `url` and `headers`. You commit the config; each developer keeps the token in their own shell.

**All servers at once.** Tools from every configured server are discovered when Claude Code connects, and all are available together, named `mcp__<server>__<tool>`. (Today Claude Code also *defers* tool definitions with tool search, so many servers cost little context.)

**Tools vs resources:**
- **Tools** = actions. Model-controlled: Claude decides to call them.
- **Resources** = content, each with a URI (`kb://index`, `issue://123`). Application-driven: the host decides how to include them.
Expose **catalogs** as resources — issue summaries, a docs tree, a database schema — so the agent *sees what exists* without exploratory tool calls. In Claude Code you type `@` to pick one (`@kb:kb://index`), and Claude also gets tools to list and read resources.

**Make MCP tools win when they are better.** If an MCP search tool is more capable than built-in Grep but has a thin description, Claude keeps using Grep. Describe what the MCP tool searches and returns.

**Build or reuse?** Use the existing community/vendor server for standard integrations (Jira, GitHub, Slack). Build a custom server only for team-specific workflows.

*In Python terms:* project scope is like `requirements.txt` in the repo; user scope is like packages in your own `~/.local`; `${GITHUB_TOKEN}` is like reading `os.environ["GITHUB_TOKEN"]` instead of hard-coding the key.

## Code

**File:** [`codes/2_4_kb_server.py`](codes/2_4_kb_server.py) · run `make run 2_4_kb_server`

Python 3.13+, `mcp` 2.3, Claude Code (your normal login). A tiny team knowledge-base server with **one resource catalog, one resource template and one tool**.
Save as `2_4_kb_server.py` in a test project folder.

```python
# 2_4_kb_server.py — mcp 2.3 (Python SDK). Started by Claude Code over stdio (see .mcp.json).
import json
from mcp.server import MCPServer

kb_server = MCPServer("team-kb")
TEAM_DOCS = {
    "deploy": "Deploy: merge to main, CI builds image, ArgoCD syncs to prod within 5 min.",
    "oncall": "On-call: PagerDuty rotation weekly, handoff Monday 10:00, runbooks in /runbooks.",
    "db-schema": "Tables: users(id, email), orders(id, user_id, total, status).",
}

@kb_server.resource("kb://index")
def doc_index() -> str:
    """Catalog of every team doc: slug and first sentence. Read this before searching."""
    return json.dumps({slug: text.split(".")[0] for slug, text in TEAM_DOCS.items()})

@kb_server.resource("kb://docs/{slug}")
def read_doc(slug: str) -> str:
    """Full text of one team doc by slug (see kb://index for slugs)."""
    return TEAM_DOCS[slug]

@kb_server.tool()
def search_kb(query: str) -> str:
    """Full-text search over team docs (deploy, on-call, DB schema). Returns matching slugs
    with their text. Use for team-internal how-to questions, not for searching code."""
    matches = {
        slug: text for slug, text in TEAM_DOCS.items() if query.lower() in text.lower()
    }
    return json.dumps(matches)  # empty {} = valid "no match", not an error

if __name__ == "__main__":
    kb_server.run()
```

Project-scoped config — commit this file. The token stays in your shell:
```json
{
  "mcpServers": {
    "kb": {
      "type": "stdio",
      "command": "uv",
      "args": ["run", "--with", "mcp", "python", "2_4_kb_server.py"]
    },
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer ${GITHUB_TOKEN}" }
    }
  }
}
```

Run it (start `claude` in the folder that holds `2_4_kb_server.py`):
```bash
claude mcp add --scope project kb -- uv run --with mcp python 2_4_kb_server.py   # writes .mcp.json for you
claude mcp list                                  # kb listed; github warns if GITHUB_TOKEN is unset
claude                                           # approve the project server, then try:
#   /mcp                                         → kb connected, 1 tool
#   "Using @kb:kb://index, which doc covers on-call?"   (type @ to autocomplete it)
```
Expected: `/mcp` shows `kb` as connected; Claude answers with the `oncall` doc ("PagerDuty rotation weekly, handoff Monday 10:00…").

**Predict first, then change and check:** delete the docstring of `search_kb`, restart Claude Code, and ask "How do we deploy?". Which tool does Claude reach for?

<details><summary>Answer</summary>

Often Grep/Bash over the repo — the MCP tool's description no longer tells Claude it searches team docs. A clear description is what makes a better MCP tool win over a built-in one.

</details>

## When to use · gotchas
- **"New teammate doesn't get the server"** → it is in user/local scope (`~/.claude.json`), not in the project's `.mcp.json`.
- **Never commit tokens.** Use `${VAR}` expansion. An unset variable leaves `${VAR}` unexpanded and `claude mcp list` warns.
- **Resources for catalogs, tools for actions.** Don't make the agent "search" just to discover what exists.
- Prefer maintained community servers for standard systems; custom ones need upkeep.
- Too many servers with thin descriptions → wrong tool picks. Description quality matters for MCP tools as much as for your own.

## Try it
*≤ 10 min.* Add a personal, experimental server at **user** scope (any public MCP URL you like, or a second copy of `2_4_kb_server.py` named `kb-dev`). Confirm in `/mcp` that it and the project's `kb` are both available. Where was each stored?

<details><summary>Solution</summary>

```bash
claude mcp add --scope user kb-dev -- uv run --with mcp python /full/path/to/kb_server.py
claude mcp list            # kb (project, .mcp.json) and kb-dev (user, ~/.claude.json)
```
The project server lives in `.mcp.json` (shared via git). The user server lives in `~/.claude.json` (only you, every project). Both load at the same time; their tools are `mcp__kb__search_kb` and `mcp__kb-dev__search_kb`.

</details>

## Quiz
**1.** The team wants every developer to get the GitHub MCP server after cloning, without committing tokens. Best setup? A) Each dev adds it with `--scope user` · B) `.mcp.json` in the repo with `"Authorization": "Bearer ${GITHUB_TOKEN}"` · C) Put the token in `.mcp.json` and make the repo private · D) Document the setup in README

<details><summary>Answer</summary>

**B.** Project scope shares the config through git; env var expansion keeps the secret out of it.

</details>

**2.** Where do personal or experimental MCP servers belong?

<details><summary>Answer</summary>

User scope, `~/.claude.json` — available in all your projects, not shared with the team.

</details>

**3.** An agent spends many tool calls listing issues just to find which ones exist. Better design?

<details><summary>Answer</summary>

Expose the issue summaries as an MCP **resource** (a catalog), so the agent sees what exists without exploratory tool calls.

</details>

**4.** You have an MCP code-search tool with semantic search, but Claude keeps using built-in Grep. First fix?

<details><summary>Answer</summary>

Improve the MCP tool's description: what it searches, what it returns, and when it beats plain text search.

</details>

**5.** Your team needs Jira access in Claude Code. Build a custom MCP server?

<details><summary>Answer</summary>

No — use the existing community/vendor Jira server. Build custom servers only for team-specific workflows.

</details>
