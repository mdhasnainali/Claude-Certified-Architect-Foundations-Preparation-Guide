# 2.5 Built-in Tools

## Goal
After this you can pick the right built-in tool — Grep, Glob, Read, Write, Edit, Bash — and explore an unknown codebase step by step instead of reading everything. *(Task statement 2.5)*

## Guess first
1. You need every caller of `issue_refund`. Glob or Grep?
2. An Edit fails with "found 2 matches". What are your options?

## Idea
| Tool | Works on | Use for | Example |
|---|---|---|---|
| **Grep** | file **contents** (regex, ripgrep syntax) | callers of a function, error messages, imports | `issue_refund\(` |
| **Glob** | file **paths / names** | files by name or extension | `**/*.test.tsx` |
| **Read** | one whole file, with line numbers | understand a file you found | — |
| **Write** | create or overwrite a whole file | new files; fallback when Edit can't find a unique anchor | — |
| **Edit** | exact string replacement in a file | targeted change to existing code | `old_string` → `new_string` |
| **Bash** | shell commands | run tests, git, builds | `pytest -x` |

**Edit's rules:** `old_string` must match **exactly** (whitespace too) and appear **exactly once**. If it appears twice, Edit fails. Then:
1. use a longer `old_string` with surrounding context so it is unique, or
2. `replace_all: true` if you really mean every occurrence, or
3. **Read + Write**: read the whole file and write the full new version — the reliable fallback.

**Explore incrementally.** Grep to find entry points → Read those files → follow the imports → Read the next file. Don't Read every file up front; it floods the context with code you never needed.

**Trace through wrappers.** Modules often re-export under new names: `from .refund import issue_refund as refund_order`. Grep for `issue_refund` then misses every caller of `refund_order`. So: first list the names a wrapper exports, then Grep for each name.

> [!WARNING]
> **Exam vs today's Claude Code**
> The exam treats Grep and Glob as standard built-in tools. Current Claude Code on Linux/macOS hides them by default and searches with `find`/`grep` through Bash; naming them in `--allowedTools` (or the Agent SDK's `allowed_tools`) brings them back. Same ideas — content search vs name search.

*In Python terms:* Glob = `pathlib.Path.glob()`, Grep = `re.search()` over file text, Edit = `str.replace()` with a "must match once" check, Write = `open(path, "w").write(...)`.

## Code

**File:** [`codes/2_5_explore.py`](codes/2_5_explore.py) · run `make run 2_5_explore`

Python 3.13+, offline, no API key. It builds a tiny fake repo and imitates the tools' rules. Paste **both blocks into one file** `2_5_explore.py`, run `python3 2_5_explore.py`.

```python
# 2_5_explore.py — part 1: Glob, Grep and wrapper tracing on a tiny fake repo. Python 3.13+, offline.
import pathlib, re, tempfile

root = pathlib.Path(tempfile.mkdtemp())
for name, text in {
    "src/billing/refund.py": "def issue_refund(order, amount):\n    return gateway.pay(-amount)\n",
    "src/billing/__init__.py": "from .refund import issue_refund as refund_order\n",
    "src/api/routes.py": "from billing import refund_order\n\ndef post_refund(req):\n    return refund_order(req.order, req.amount)\n",
    "src/api/routes.test.py": "def test_post_refund():\n    assert True\n",
    "src/jobs/nightly.py": "from billing.refund import issue_refund\nissue_refund(o, 5)\nissue_refund(o, 7)\n",
}.items():
    (root / name).parent.mkdir(parents=True, exist_ok=True)
    (root / name).write_text(text)

glob = lambda pattern: sorted(
    str(p.relative_to(root)) for p in root.glob(pattern)
)  # names
grep = lambda rx: sorted(
    {
        str(p.relative_to(root))
        for p in root.rglob("*.py")
        if re.search(rx, p.read_text())
    }
)  # contents

print("Glob **/*.test.py   →", glob("**/*.test.py"))
print("Grep issue_refund\\( →", grep(r"issue_refund\("))
aliases = re.findall(
    r"issue_refund as (\w+)", (root / "src/billing/__init__.py").read_text()
)
print("Wrapper exports     →", aliases, "| Grep each:", grep(rf"{aliases[0]}\("))
```

```python
# 2_5_explore.py — part 2: Edit's "exact and unique" rule
def edit(path: str, old: str, new: str) -> None:
    text = (root / path).read_text()
    if (n := text.count(old)) != 1:
        raise ValueError(f"{n} matches for {old!r}: add more context, or Read + Write")
    (root / path).write_text(text.replace(old, new))

try:
    edit("src/jobs/nightly.py", "issue_refund(o, ", "issue_refund(order=o, amount=")
except ValueError as e:
    print("Edit                →", e)
edit("src/jobs/nightly.py", "issue_refund(o, 7)", "issue_refund(o, 8)")
print("Edit with context   → ok")
```

Expected output:
```
Glob **/*.test.py   → ['src/api/routes.test.py']
Grep issue_refund\( → ['src/billing/refund.py', 'src/jobs/nightly.py']
Wrapper exports     → ['refund_order'] | Grep each: ['src/api/routes.py']
Edit                → 2 matches for 'issue_refund(o, ': add more context, or Read + Write
Edit with context   → ok
```
Notice line 2: Grep for the original name **misses** `routes.py`. Only tracing the wrapper's export finds it.

**Predict first, then change and run:** change the Glob pattern to `*.test.py` (no `**/`). What prints?

<details><summary>Answer</summary>

`[]` — without `**/` the pattern only looks in the top folder. `**/` means "at any depth".

</details>

## When to use · gotchas
- **Content → Grep. Name/path → Glob.** Exam questions often swap them in a wrong option.
- Grep is ripgrep regex: escape metacharacters (`issue_refund\(`, `interface\{\}`).
- Grep skips `.gitignore`d files; Glob does not.
- Edit is exact — no regex, no fuzzy match. One space of difference misses.
- Prefer Edit for small changes (safe, reviewable); fall back to Read + Write when no unique anchor exists.
- Reading everything first = context exhaustion. Search, then read what the search points to.

## Try it
*≤ 10 min.* Add a `replace_all: bool = False` parameter to `edit()` that replaces every occurrence when `True`, like the real Edit tool. Use it to rename every `issue_refund(o, ` call in `nightly.py`.

<details><summary>Solution</summary>

```python
def edit(path: str, old: str, new: str, replace_all: bool = False) -> None:
    text = (root / path).read_text()
    n = text.count(old)
    if n == 0 or (n > 1 and not replace_all):
        raise ValueError(f"{n} matches for {old!r}: add more context, or Read + Write")
    (root / path).write_text(text.replace(old, new))

edit("src/jobs/nightly.py", "issue_refund(o, ", "issue_refund(order=o, amount=", replace_all=True)
print((root / "src/jobs/nightly.py").read_text())
```
Both calls now read `issue_refund(order=o, amount=...)`.

</details>

## Quiz
**1.** You must find every file that calls `validate_token(`. Which tool? A) Glob `**/*token*` · B) Grep `validate_token\(` · C) Read every file in `src/` · D) Bash `ls -R`

<details><summary>Answer</summary>

**B.** Content search. A matches file names, not calls; C wastes context; D lists names only.

</details>

**2.** Find all test files named like `Button.test.tsx` anywhere in the repo.

<details><summary>Answer</summary>

Glob `**/*.test.tsx`.

</details>

**3.** An Edit fails because `return None` appears 6 times in the file. What are the reliable options?

<details><summary>Answer</summary>

Make `old_string` unique with surrounding context; use `replace_all` if every occurrence should change; or Read the whole file and Write the new version.

</details>

**4.** A new developer agent reads all 400 files of a repo before answering, then gives vague answers. Better approach?

<details><summary>Answer</summary>

Build understanding incrementally: Grep for entry points, Read those files, follow imports — only what the question needs.

</details>

**5.** Grep for `send_email(` finds 3 callers, but production logs show more. The module `notify/__init__.py` has `from .mail import send_email as notify_user`. What next?

<details><summary>Answer</summary>

Trace the wrapper: list its exported names (`notify_user`), then Grep for each of them too.

</details>
