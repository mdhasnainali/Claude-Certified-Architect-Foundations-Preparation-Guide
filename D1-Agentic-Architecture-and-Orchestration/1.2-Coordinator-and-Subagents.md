# 1.2 Coordinator and Subagents

## Goal
After this you can design a hub-and-spoke multi-agent system, and find the real root cause when its output is incomplete. *(Task statement 1.2)*

## Guess first
1. A research report on "AI in creative industries" covers only visual arts. Every subagent did its own job well. Which agent is at fault?
2. Should subagents talk to each other directly, to save time?

## Idea
**Hub-and-spoke:** one **coordinator** (the hub) and several specialist **subagents** (the spokes). Every message between agents goes through the hub. The coordinator does five jobs:

1. **Decompose** — split the task into subtasks.
2. **Delegate** — choose which subagents to call. Not always all of them.1
3. **Aggregate** — combine the results.
4. **Evaluate and refine** — look for gaps, send targeted follow-ups, combine again.
5. **Route and handle errors** — in one place, so the system is observable and consistent.

Subagents have **isolated context**: they don't see the coordinator's conversation. They know only what the coordinator puts in their prompt (details in [1.3 Spawning Subagents and Passing Context](1.3-Spawning-Subagents-and-Passing-Context.md)).

*In Python terms:* like ThreadPoolExecutor. `main()` submits jobs with arguments and collects return values. Workers don't share variables and don't call each other. `main()` decides what to submit and what to do with the results.

**Design rules the exam tests:**
- **Choose subagents by query complexity.** A simple fact question should not run the full search → analyse → synthesise pipeline. Anthropic's research system scales effort: about 1 agent with 3–10 tool calls for a simple fact, 2–4 subagents for a comparison, 10+ for complex research.
- **Breadth first.** The biggest risk is a decomposition that is **too narrow**. If the coordinator splits "creative industries" into only digital art, graphic design and photography, every subagent can succeed and the report still misses music, writing and film.
- **Partition the scope.** Give each subagent a distinct subtopic or source type, so they don't do the same work twice.
- **Iterative refinement loop.** Synthesise → check coverage → re-delegate targeted searches for the gaps → synthesise again, until coverage is good enough (with a limit).
- **Goals and quality criteria, not step lists.** Tell the coordinator *what* good output looks like ("every sub-area has 2+ sources; name gaps"). A fixed step list stops subagents from adapting to what they find.
- **Everything through the coordinator.** No direct subagent-to-subagent messages. You get one place for logs, one error policy, and control over what information flows where.

**Root-cause rule:** read the coordinator's delegation log first. If the subagents did their *assigned* work well but the output misses areas, the fault is upstream: the decomposition. Don't "fix" a downstream agent that is working correctly.

**Cost:** multi-agent systems use many more tokens (Anthropic measured ~4× chat for one agent, ~15× chat for multi-agent). They fit wide, parallel work. They fit badly when every step needs shared context or tight coordination — most coding tasks.

```python
# 1_2_coordinator_and_subagents.py — claude-agent-sdk 0.2.188. Run: uv run --with claude-agent-sdk python 1_2_coordinator_and_subagents.py
import asyncio
from claude_agent_sdk import AgentDefinition, AssistantMessage, ClaudeAgentOptions, ResultMessage, ToolUseBlock, query

COORDINATOR = """You lead a research team. Goal: a cited brief that covers EVERY major
sub-area of the topic. First list the sub-areas, aiming for breadth.
Give each searcher a DIFFERENT sub-area. Quality bar: 2+ sources per sub-area;
name gaps, never hide them. If synthesis shows a gap, search again, then re-synthesize."""

AGENTS = {
    "searcher": AgentDefinition(
        description="Web research on ONE assigned sub-area. Returns claims with sources.",
        prompt="Research only your sub-area. Return a JSON list of {claim, url, date}.",
        tools=["WebSearch", "WebFetch"], model="haiku"),
    "synthesizer": AgentDefinition(
        description="Merges findings given in its prompt into a cited brief. Lists gaps.",
        prompt="Use only the findings in your prompt. Keep each claim's source.", tools=["Read"]),
}
async def main():
    opts = ClaudeAgentOptions(system_prompt=COORDINATOR, agents=AGENTS, max_budget_usd=1.0,
                              allowed_tools=["Agent", "WebSearch", "WebFetch"])
    async for m in query(prompt="Topic: impact of AI on creative industries", options=opts):
        if isinstance(m, AssistantMessage) and m.parent_tool_use_id is None:  # coordinator only
            for b in m.content:
                if isinstance(b, ToolUseBlock) and b.name in ("Agent", "Task"):
                    print("DELEGATE →", b.input.get("subagent_type"), "|", b.input.get("description"))
        if isinstance(m, ResultMessage):
            print(m.subtype, m.result if m.subtype == "success" else "")

asyncio.run(main())
```

Expected output (sub-areas and wording vary):
```
DELEGATE → searcher | AI in visual art and design
DELEGATE → searcher | AI in music production
DELEGATE → searcher | AI in writing and publishing
DELEGATE → searcher | AI in film and video
DELEGATE → synthesizer | Merge findings into a cited brief
success # Impact of AI on creative industries ...
```
The `DELEGATE` lines **are** your coordinator log. This is where you check the decomposition. (`"Agent"` is today's name of the exam's `"Task"` tool — the code matches both.)

**Predict first, then change and run:** replace `COORDINATOR` with `"Research the topic. Use the searcher, then the synthesizer."` How will the `DELEGATE` lines change?

<details><summary>Answer</summary>

Usually fewer and narrower delegations — often one broad searcher, overlapping work, and no named gaps. Nothing told the coordinator what "good coverage" means, so it takes the shortest path.

</details>

## When to use · gotchas
- **Use** a coordinator when the work is wide and splits into independent parts (research across sources, many documents). **Skip it** for small or tightly coupled tasks — one agent is cheaper and simpler.
- **Over-spawning:** without guidance, a coordinator may start many subagents for a simple question. Put effort rules in its prompt and cap spend.
- **Vague delegation** causes duplicate work and gaps. Each delegation needs: an objective, an output format, which tools or sources to use, and clear boundaries.
- **Waiting:** the coordinator waits for the slowest subagent in a batch. One slow subagent slows the whole round.
- **Exam distractor:** "improve the search agent's queries" or "tell the synthesis agent to find gaps" when the coordinator's log shows a narrow decomposition. Fix the coordinator.

## Quiz
**1.** A competitor-analysis system must compare 5 competitors named in the request. Reports cover only 2. Logs show the coordinator created two tasks: "Competitor A pricing" and "Competitor B pricing". Each subagent's output is accurate. Root cause? A) Search agent queries too narrow · B) Synthesis agent drops data · C) Coordinator decomposition too narrow · D) Context window too small

<details><summary>Answer</summary>

**C.** The subagents did their assigned work correctly. What they were assigned was incomplete. A, B and D blame parts that work.

</details>

**2.** "What year was Company X founded?" runs through search → analysis → synthesis: 90 seconds and $0.40. Best fix?

<details><summary>Answer</summary>

Let the coordinator analyse query complexity and choose subagents dynamically — here one search (or a direct answer), not the full pipeline.

</details>

**3.** Why route all subagent communication through the coordinator instead of letting the search agent message the synthesis agent directly?

<details><summary>Answer</summary>

Observability (one log of every hand-off), consistent error handling, and controlled information flow (the coordinator decides what each agent sees).

</details>

**4.** Two searchers return almost the same sources. Fix?

<details><summary>Answer</summary>

Partition the scope in the delegation: give each searcher a distinct subtopic or source type, and state the boundaries.

</details>

**5.** Which coordinator prompt is better? (a) "1. Search 'AI art'. 2. Search 'AI music'. 3. Summarise." (b) "Goal: cover every major sub-area; 2+ sources each; name gaps."

<details><summary>Answer</summary>

**(b).** Goals and quality criteria let the coordinator and subagents adapt to what they discover. (a) hard-codes a narrow decomposition.

</details>
