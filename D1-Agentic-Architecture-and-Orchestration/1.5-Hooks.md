# 1.5 Hooks

## Goal
After this you can choose between `PreToolUse` and `PostToolUse`, and write a hook that blocks a policy breach or cleans tool data before Claude reads it. *(Task statement 1.5)*

## Guess first
1. Three MCP tools return dates as `1764000000`, `"2025-11-24T16:00:00Z"` and `"24/11/2025"`. Where is the most reliable place to fix this, so the agent is never confused?
2. Can a `PostToolUse` hook stop a refund that is too large?

## Idea
A **hook** is your own function that the Agent SDK calls at a fixed point in the loop. It runs in your process, outside Claude's context window. It runs **every time** — that is the deterministic guarantee prompts can't give.

Two hooks matter most for the exam:

| Hook | When it fires | What it can do | Typical use |
|---|---|---|---|
| `PreToolUse` | **Before** the tool runs | Decide `allow` / `deny` / `ask` (or `defer`); rewrite the input (`updatedInput`) | Block refunds over $500 and send Claude to the escalation workflow |
| `PostToolUse` | **After** the tool returns, before Claude sees the result | Add a note (`additionalContext`); replace the result (`updatedToolOutput`) | Turn Unix timestamps, ISO 8601 strings and numeric status codes into one format |

**Key point:** `PostToolUse` cannot undo anything. The tool already ran — the refund is already paid. To prevent an action, use `PreToolUse`.

**How you register a hook:**
- `ClaudeAgentOptions(hooks={"PreToolUse": [HookMatcher(matcher="...", hooks=[my_fn])]})`
- `matcher` filters by tool name: one name, a `|` list, or a regex. MCP tools are named `mcp__<server>__<tool>`, so `"^mcp__"` matches every MCP tool.
- The callback: `async def my_fn(input_data, tool_use_id, context) -> dict`. `input_data` has `tool_name`, `tool_input` (and `tool_response` in `PostToolUse`). Return `{}` for "no decision".
- Decisions go inside `hookSpecificOutput`, not at the top level.
- Several hooks on one call run in parallel; the strictest decision wins: **deny > defer > ask > allow**.

**Block and redirect.** A deny is not a dead end. Its `permissionDecisionReason` reaches Claude as the tool result. Write the alternative there: "Refunds over $500 need a human. Call escalate_to_human." Now the policy is guaranteed *and* the customer still gets help.

*In Python terms:* `PreToolUse` is like a FastAPI middleware that can return 403 before your route runs. `PostToolUse` is like response middleware that rewrites the body before the client gets it.

## Code

**File:** [`codes/1_5_hooks.py`](codes/1_5_hooks.py) · run `make run 1_5_hooks`

Python 3.13+. Runs offline (no API key). Save as `1_5_hooks.py`, run `python3 1_5_hooks.py`.

```python
# 1_5_hooks.py — Python 3.13+. Runs offline: python3 1_5_hooks.py
import asyncio, json
from datetime import datetime, timezone
STATUS = {0: "pending", 1: "shipped", 2: "delivered", 9: "cancelled"}

def normalize(rec: dict) -> dict:
    if isinstance(rec.get("updated"), (int, float)):     # Unix seconds → ISO 8601
        rec["updated"] = datetime.fromtimestamp(rec["updated"], timezone.utc).isoformat()
    if isinstance(rec.get("status"), int):               # numeric code → word
        rec["status"] = STATUS.get(rec["status"], f"unknown({rec['status']})")
    return rec

async def normalize_output(inp, tool_use_id, ctx):      # PostToolUse, matcher "^mcp__"
    rec = normalize(json.loads(inp["tool_response"]["content"][0]["text"]))
    return {"hookSpecificOutput": {"hookEventName": "PostToolUse",
            "updatedToolOutput": {"content": [{"type": "text", "text": json.dumps(rec)}]}}}

async def refund_limit(inp, tool_use_id, ctx):          # PreToolUse, matcher process_refund
    if inp["tool_input"]["amount"] <= 500:
        return {}
    return {"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny",
            "permissionDecisionReason": "Refunds over $500 need a human. Call escalate_to_human."}}

async def demo():
    raw = {"content": [{"type": "text", "text": '{"order": "ORD-9", "status": 1, "updated": 1764000000}'}]}
    print((await normalize_output({"tool_response": raw}, None, None))["hookSpecificOutput"]["updatedToolOutput"])
    print(await refund_limit({"tool_input": {"amount": 120}}, None, None))
    print(await refund_limit({"tool_input": {"amount": 900}}, None, None))

asyncio.run(demo())
```

Expected output:
```
{'content': [{'type': 'text', 'text': '{"order": "ORD-9", "status": "shipped", "updated": "2025-11-24T16:00:00+00:00"}'}]}
{}
{'hookSpecificOutput': {'hookEventName': 'PreToolUse', 'permissionDecision': 'deny', 'permissionDecisionReason': 'Refunds over $500 need a human. Call escalate_to_human.'}}
```

Wiring it into an agent:
```python
from claude_agent_sdk import ClaudeAgentOptions, HookMatcher

options = ClaudeAgentOptions(
    mcp_servers={"support": support_server},
    hooks={
        "PostToolUse": [HookMatcher(matcher="^mcp__", hooks=[normalize_output])],
        "PreToolUse": [HookMatcher(matcher="mcp__support__process_refund", hooks=[refund_limit])],
    },
)
```

The demo assumes an MCP result is one JSON text block. Print `inp["tool_response"]` once on your real server to confirm the shape. The replacement must match the tool's output shape (MCP output is not schema-checked; built-in tools are).

2. `"status": "unknown(7)"` — unknown codes stay visible instead of being dropped.

## When to use · gotchas
- **Hooks when the rule must always hold** (money limits, compliance, data formats). **Prompts when a miss is cheap.**
- `PostToolUse` with `decision: "block"` only adds a reason next to the original output. It does not undo or hide anything. To change what Claude sees, use `updatedToolOutput`.
- `updatedInput` **replaces the whole input.** Copy the unchanged fields too, and put it inside `hookSpecificOutput`.
- Return new objects; don't mutate the input you received.
- A `PreToolUse` hook that times out blocks the call (default timeout 600 s). Keep hooks fast.
- `PostToolUse` can also **trim** big tool results to the fields that matter — fewer tokens in context (Domain 5).
- Older field name: `updatedMCPToolOutput` (MCP tools only). Prefer `updatedToolOutput`.

## Try it
*≤ 10 min.* `lookup_order` returns 40+ fields, but the agent needs only `order_id`, `status`, `total`, `items`, `updated`. Write a `PostToolUse` hook `trim_order` that keeps only those fields.

<details><summary>Solution</summary>

```python
KEEP = ("order_id", "status", "total", "items", "updated")

async def trim_order(inp, tool_use_id, ctx):        # PostToolUse, matcher: mcp__support__lookup_order
    rec = json.loads(inp["tool_response"]["content"][0]["text"])
    small = {k: rec[k] for k in KEEP if k in rec}
    return {"hookSpecificOutput": {"hookEventName": "PostToolUse",
            "updatedToolOutput": {"content": [{"type": "text", "text": json.dumps(small)}]}}}
```
Test it offline like `demo()`: pass a fake record with extra fields and print the result.

</details>

## Quiz
**1.** Policy: refunds over $500 need human approval. Logs show the agent processed a $720 refund, although the system prompt states the rule. Best fix? A) Repeat the rule at the end of the prompt · B) A `PreToolUse` hook on `process_refund` that denies amounts over $500 and tells the agent to call `escalate_to_human` · C) A `PostToolUse` hook that logs large refunds · D) Ask the agent to rate its confidence before refunds

<details><summary>Answer</summary>

**B.** A guaranteed rule needs a deterministic check before the action. A and D are still probabilistic. C runs after the money is gone.

</details>

**2.** The agent misreads order dates because three tools use three formats. Most reliable fix?

<details><summary>Answer</summary>

A `PostToolUse` hook that normalises every format before the model sees the result. A prompt saying "convert the dates" is probabilistic and costs reasoning every turn.

</details>

**3.** Two `PreToolUse` hooks match the same call. One returns `allow`, the other `deny`. Result?

<details><summary>Answer</summary>

Denied. The strictest decision wins: deny > defer > ask > allow.

</details>

**4.** Fix the bug: a `PostToolUse` hook on `process_refund` returns `permissionDecision: "deny"` for amounts over $500, but large refunds still go through.

<details><summary>Answer</summary>

`PostToolUse` fires after the refund ran, and `permissionDecision` belongs to `PreToolUse`. Move the check to a `PreToolUse` hook.

</details>

**5.** Which matcher hits every tool from the MCP server named `billing`?

<details><summary>Answer</summary>

`"mcp__billing__.*"` (a regex). MCP tool names follow `mcp__<server>__<tool>`.

</details>
