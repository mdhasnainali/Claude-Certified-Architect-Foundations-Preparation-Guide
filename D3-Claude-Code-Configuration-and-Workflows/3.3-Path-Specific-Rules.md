# 3.3 Path-Specific Rules

## Goal
After this you can scope conventions to file patterns with `paths:` in `.claude/rules/`, and know when that beats a subdirectory CLAUDE.md. *(Task statement 3.3)*

## Guess first
1. Test files live next to the code they test, in 40 folders (`Button.test.tsx` next to `Button.tsx`). Where do you put "test conventions" so they always apply to tests?
2. Does a path-scoped rule cost context when Claude never touches a matching file?

## Idea
A file in `.claude/rules/` can start with YAML frontmatter:

```yaml
---
paths:
  - "**/*.test.tsx"
  - "terraform/**/*"
---
```

- The rule **loads only when Claude reads, writes or edits a file that matches** one of the glob patterns. Otherwise it costs nothing.
- **No `paths:`** → the rule loads every session, like CLAUDE.md.
- Globs: `**/*.test.tsx` = test files anywhere; `src/api/**/*` = everything under `src/api/`; `"src/**/*.{ts,tsx}"` = both extensions.

**Why globs beat directory CLAUDE.md files** (official sample question 6):
- A subdirectory CLAUDE.md is **bound to one folder**. Test files spread across the whole codebase would need a copy in every folder.
- A glob rule matches **by file type, wherever the file is**: one `tests.md` with `**/*.test.tsx` covers all of them.
- Wrong options in that question: one big root CLAUDE.md with headings ("Claude must infer which section applies" — unreliable), skills per code type (need invocation, not automatic), CLAUDE.md per subdirectory (directory-bound).

**Layout for a mixed codebase:**
```
.claude/rules/
├── react.md       paths: ["src/components/**/*.tsx"]
├── api.md         paths: ["src/api/**/*"]
├── tests.md       paths: ["**/*.test.ts", "**/*.test.tsx"]
└── terraform.md   paths: ["terraform/**/*"]
```

**One caveat (current docs):** path-scoped rules enter the conversation when triggered, so `/compact` summarises them away until a matching file is touched again. A rule that must always survive belongs in the root CLAUDE.md or a rule without `paths:`.

*In Python terms:* a subdirectory CLAUDE.md is like a `conftest.py` — it only applies inside its folder. A glob rule is like pytest collecting every `test_*.py` file by name pattern, wherever it lives.

## Code

**File:** [`codes/3_3_setup.sh`](codes/3_3_setup.sh)

Bash + Claude Code 2.1.x. Run inside `claude-demo/`: save as `3_3_setup.sh`, run `bash 3_3_setup.sh`.

```bash
#!/usr/bin/env bash
# 3_3_setup.sh — run inside claude-demo/. Adds path-scoped rules and files to trigger them.
set -euo pipefail
mkdir -p .claude/rules src/ui src/api infra/terraform
cat > .claude/rules/tests.md <<'MD'
---
paths:
  - "**/*.test.tsx"
  - "**/*.test.ts"
---
# Test conventions (loads only for test files, wherever they live)
- Use React Testing Library; query by role, never by CSS class.
- When this rule is active, start your reply with [TEST-RULE].
MD
cat > .claude/rules/terraform.md <<'MD'
---
paths: ["infra/terraform/**/*"]
---
# Terraform conventions
- Every resource has tags {team, env}. No hard-coded regions.
MD
echo "export const Button = () => <button>Ok</button>;" > src/ui/Button.tsx
echo "test('renders', () => {});" > src/ui/Button.test.tsx
echo "export const getUser = () => null;" > src/api/users.ts
grep -l '^paths' .claude/rules/*.md
```

Expected output:
```
.claude/rules/terraform.md
.claude/rules/tests.md
```
Then start a **new** `claude` session and ask, one at a time:
1. "Read src/api/users.ts and summarise it." → normal reply, **no** `[TEST-RULE]`.
2. "Read src/ui/Button.test.tsx and add a test that the button is clickable." → reply starts with `[TEST-RULE]` and uses `getByRole`.

The marker line is a learning trick to *see* the rule load; don't keep it in real rules.

**Predict first, then check:** in a fresh session, ask "What are our test conventions?" without touching any file. Does Claude know them?

<details><summary>Answer</summary>

Usually not — no matching file was read, so the rule never loaded. That's the point (no wasted context), and also the trade-off: path-scoped rules guide work *on* matching files, they aren't a general knowledge base.

</details>

## When to use · gotchas
- Convention tied to a **file type spread everywhere** (tests, migrations, `*.proto`) → glob rule.
- Convention tied to **one folder** → a subdirectory CLAUDE.md works too; a rule with `src/api/**/*` also works.
- Always-needed rules → no `paths:` (or root CLAUDE.md).
- Quote globs in YAML (`"**/*.ts"`) — `*` at the start of a YAML value needs quotes.
- Invalid frontmatter → the rule loads as if it had no `paths:` (every session). Check with `claude --debug`.

## Try it
*≤ 10 min.* Add a rule for database migrations in `db/migrations/*.sql` **and** `services/*/migrations/*.sql`: "never drop a column in the same release that stops writing to it".

<details><summary>Solution</summary>

```bash
cat > .claude/rules/migrations.md <<'MD'
---
paths:
  - "db/migrations/*.sql"
  - "services/*/migrations/*.sql"
---
# Migrations
- Never drop a column in the same release that stops writing to it. Drop it one release later.
MD
```

</details>

## Quiz
**1.** React components, API handlers and DB models each have conventions; test files sit next to the code everywhere. Most maintainable way to apply the right conventions automatically? A) `.claude/rules/` files with `paths:` globs · B) All conventions in the root CLAUDE.md under headings · C) A skill per code type · D) A CLAUDE.md in every subdirectory

<details><summary>Answer</summary>

**A.** Globs match by file pattern regardless of folder. B relies on inference, C on invocation, D is directory-bound.

</details>

**2.** When does a rule with `paths: ["terraform/**/*"]` load?

<details><summary>Answer</summary>

When Claude reads, writes or edits a file matching that pattern — not at session start.

</details>

**3.** Why prefer a glob rule over subdirectory CLAUDE.md files for test conventions?

<details><summary>Answer</summary>

Test files are spread across many directories; one glob (`**/*.test.tsx`) covers all, while CLAUDE.md files are bound to one directory each.

</details>

**4.** What happens to a rule in `.claude/rules/` without a `paths:` field?

<details><summary>Answer</summary>

It loads every session, like the project CLAUDE.md.

</details>

**5.** Write the frontmatter for a rule that applies to every `.tsx` and `.ts` file under `src/`.

<details><summary>Answer</summary>

`paths: ["src/**/*.{ts,tsx}"]` (or two patterns).

</details>
