# 3.6 Claude Code in CI

## Goal
After this you can run Claude Code in a pipeline without hangs, get machine-readable findings, give it project context, and avoid duplicate PR comments. *(Task statement 3.6)*

## Guess first
1. Your CI job runs `claude "Review this PR"` and hangs forever. Why?
2. After every new commit the bot re-posts the same 12 comments. What's missing?

## Idea
**`-p` (`--print`) = non-interactive mode.** Claude processes the prompt, prints the result, and exits — no waiting for input. Without it, a pipeline job waits for a terminal that never answers (official sample question 10; `CLAUDE_HEADLESS=true`, `--batch`, or `< /dev/null` are not the fix).

**Structured output for automation:** `--output-format json` returns a JSON envelope (result, session ID, usage, cost). Add **`--json-schema '<schema>'`** and the findings arrive in `structured_output`, matching your schema — ready to post as inline PR comments. Check that `structured_output` exists before using it.

**Project context = CLAUDE.md.** CI-invoked Claude Code reads the repo's CLAUDE.md like a developer session does. Put there what CI needs: testing standards, valuable vs low-value tests, available fixtures, review criteria. Better CLAUDE.md → better generated tests, fewer useless ones.

**Independent review instance.** The session that *generated* code is a weak reviewer of it (it keeps its own reasoning). Run the review as a separate `claude -p` invocation ([4.6 Multi-Pass Review](../D4-Prompt-Engineering-and-Structured-Output/4.6-Multi-Pass-Review.md)).

**Avoid duplicate comments.** When re-running after new commits, include the **prior findings** in the prompt and ask for **only new or still-unaddressed** issues.

**Avoid duplicate tests.** When generating tests, give the **existing test files** as context so Claude doesn't suggest scenarios that are already covered.

**Permissions in CI:** nobody can answer a prompt, so pre-approve what the job needs (`--allowedTools "Read,Grep,Glob"`) and nothing more. The official GitHub Action (`anthropics/claude-code-action@v1`) wraps the same CLI.

*In Python terms:* `-p` is like running a script instead of the REPL; `--json-schema` is like `json.loads` with a guaranteed shape, so the next pipeline step can trust the fields.

## Code

**File:** [`codes/3_6_ci_review.sh`](codes/3_6_ci_review.sh)

Bash + Claude Code 2.1.x + `jq`. Needs `ANTHROPIC_API_KEY` in CI secrets. Save as `scripts/ci_review.sh` in a repo.

```bash
#!/usr/bin/env bash
# ci_review.sh — Claude Code 2.1.x in CI. Needs ANTHROPIC_API_KEY. Run after checkout of the PR branch.
set -euo pipefail
SCHEMA='{"type":"object","required":["findings"],"properties":{"findings":{"type":"array","items":{
 "type":"object","required":["file","line","severity","issue","fix"],"properties":{"file":{"type":"string"},
 "line":{"type":"integer"},"severity":{"enum":["high","medium","low"]},"issue":{"type":"string"},
 "fix":{"type":"string"}}}}}}'
mkdir -p .review
PRIOR=$(cat .review/prior-findings.json 2>/dev/null || echo '{"findings":[]}')

git diff origin/main...HEAD | claude -p "Review the PR diff on stdin with the review criteria in CLAUDE.md.
Report only NEW or still-unfixed issues. Already reported earlier: $PRIOR" \
  --output-format json --json-schema "$SCHEMA" --allowedTools "Read,Grep,Glob" \
  | jq '.structured_output // {"findings": []}' > .review/findings.json

jq -r '.findings[] | "::warning file=\(.file),line=\(.line)::[\(.severity)] \(.issue) Fix: \(.fix)"' .review/findings.json
cp .review/findings.json .review/prior-findings.json   # next run skips these
```

Expected output in the job log (findings vary):
```
::warning file=app/pay.py,line=42::[high] float used for money Fix: use Decimal
```
`::warning file=…,line=…::` is GitHub Actions' annotation format, so each finding appears inline on the PR diff. (Keep `.review/prior-findings.json` between runs with an Actions cache or artifact.)

The workflow that calls it:
```yaml
name: claude-review
on: pull_request
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with: { fetch-depth: 0 }          # full history for git diff origin/main...HEAD
      - run: curl -fsSL https://claude.ai/install.sh | bash && echo "$HOME/.local/bin" >> "$GITHUB_PATH"
      - run: bash scripts/ci_review.sh
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

**Predict first, then check:** delete `-p` from the script and run the job. What happens?

<details><summary>Answer</summary>

The job hangs: interactive Claude Code waits for input that never comes, until the CI timeout kills it. `-p` is the documented non-interactive mode.

</details>

## When to use · gotchas
- Always `-p` in scripts and CI.
- Parse `structured_output`, never scrape free text, and handle its absence (refusal or failed run).
- Grant only the tools the job needs; CI has nobody to approve prompts.
- Review in a separate invocation from generation.
- Pass prior findings (reviews) and existing tests (test generation) to prevent duplicates.
- The CLAUDE.md in the repo is your CI "system prompt": keep review criteria and test standards there.

## Try it
*≤ 10 min.* Write the `claude -p` command for **test generation** in CI: it gets the changed file and the existing tests, and must return `{"tests": [{"name", "code", "covers"}]}`, skipping scenarios already covered.

<details><summary>Solution</summary>

```bash
FILE=src/billing/invoice.py
claude -p "Write pytest tests for the changes in $FILE. Follow the testing standards and fixtures
in CLAUDE.md. Existing tests are in tests/billing/ — read them and do NOT repeat covered scenarios.
Prefer edge cases (rounding, empty invoices, currency)." \
  --output-format json --allowedTools "Read,Grep,Glob" \
  --json-schema '{"type":"object","required":["tests"],"properties":{"tests":{"type":"array","items":{"type":"object","required":["name","code","covers"],"properties":{"name":{"type":"string"},"code":{"type":"string"},"covers":{"type":"string"}}}}}}' \
  | jq '.structured_output.tests'
```

</details>

## Quiz
**1.** A pipeline runs `claude "Analyze this PR for security issues"` and hangs, waiting for input. Fix? A) `claude -p "…"` · B) `CLAUDE_HEADLESS=true` · C) `claude "…" < /dev/null` · D) `claude --batch "…"`

<details><summary>Answer</summary>

**A.** `-p`/`--print` is the documented non-interactive mode; B and D don't exist; C is a workaround that doesn't address Claude Code's syntax.

</details>

**2.** Findings must be posted automatically as inline PR comments. Which flags?

<details><summary>Answer</summary>

`--output-format json` with `--json-schema` — then read `structured_output`.

</details>

**3.** After each new commit the bot repeats old comments. Fix?

<details><summary>Answer</summary>

Include the prior review findings in the prompt and ask for only new or still-unaddressed issues.

</details>

**4.** CI-generated tests are low-value and duplicate existing ones. Two fixes?

<details><summary>Answer</summary>

Document testing standards, valuable test criteria and fixtures in CLAUDE.md; provide the existing test files in context.

</details>

**5.** Why review generated code in a separate Claude invocation?

<details><summary>Answer</summary>

The generating session keeps its own reasoning and is less likely to question its decisions; an independent instance catches more.

</details>
